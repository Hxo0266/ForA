# ForA · 自主学术助理系统

**Autonomous Academic Aid Assistant**（简称 ForA / AAAA / Four A）　版本 **1.2.0**

一套把「课程材料进去 → 结构化知识出来」彻底自动化的个人学习流水线。材料丢进 `0_inbox/`，剩下的交给脚本。

---

## 解决什么问题

每门课都会产生一堆散落的材料：讲义、作业、小测、期中考卷、期末考卷、错题。人工归位既慢又容易漏，而且**漏了很难发现**——你看不到「本该在那儿但不在那儿」的东西。

ForA 把这件事变成一条**有闸门的流水线**：进料前检查、出料后核对，任何一步不符合约定都会当场报出来，而不是等某天流程莫名失败才回头查。

---

## 目录结构

每门课程是一个独立工作区：

| 目录 | 用途 |
|:--|:--|
| `0_inbox/` | 进料口。任何新材料先扔这里，由分类器归位 |
| `1_Syllabus/` | 教学大纲 |
| `2_Textbook&Lecture_PPT/` | 教材与讲义原件 |
| `3_Essence/` | **提炼产物**：讲义 → 结构化笔记 + 插图 |
| `4_Assignment/` | 作业 |
| `5_Quiz/` | 小测 |
| `6_Midterm Examination/` | 期中考 |
| `7_Final Examination/` | 期末考 |
| `8_Correction_Notebook/` | 错题本 |
| `10_Others/` | 暂未归类 |
| `_System/` | 流水线本体：税表、引擎、教训库、日志 |

`_System/` 是整个系统的重心：

- **`taxonomy.json`** — 唯一事实源。目录叫什么、什么关键词归哪一类，全部由它声明，脚本只读它。
- **`scripts/health_check.py`** — 开工检查（O1–O6）+ 收工核对（AIE 系列）双闸门。
- **`scripts/run_pipeline.py`** — 分类与提炼主流程。
- **`ERROR_LOG.md`** — **教训库**。每一次踩坑都编号归档（AIE-nnn），并配一条可执行的自动核对。
- **`WORKFLOW.md`** — 操作手册与流程约定。

## 设计里我认为最值钱的两条

### 1. 只会 PASS 的检查等于没有检查

教训库里每一条 AIE-xxx 都必须配一个**能真的失败**的自动核对函数，而且这个函数内部要做**故障注入自测**：先构造一个已知有缺陷的临时环境，确认检查确实会报错，再去检查真实工作区。

如果检查连自己造的假缺陷都报不出来，它就直接 FAIL——因为它已经失去意义了。

### 2. 假警报比没警报更糟

任何「这个目录里有没有东西」的检查都必须排除占位文件（`README.md` / `_keep.md` / `.gitkeep`）。否则 `0_inbox/README.md` 会被永远报成「Inbox 残留」，用户天天看假警报，久而久之就会无视**所有**警告——包括真的那一条。

同理，「这条教训无法自动核对」不是默认选项。要把某条标成「需人工核对」，必须举证「这个缺陷没有可观测的静态特征」。

## 质量现状

```
开工检查：通过 6 / 关注 0 / 待办 0 / 严重 0
收工核对：通过 28 / 关注 0 / 待办 0 / 严重 0
教训库自检：28 条全过，命中 0 条
```

当前只部署了 **1 门课程**（`CHM1001`）。更多课程接入时，`_System/` 从母版同步。

---

## 关于 `skills/`

`skills/` 下是三套可复用的工作流定义，同时也是本仓库流水线的组成部分：

| Skill | 作用 |
|:--|:--|
| `course-inbox-triage` | Inbox 分类：把 `0_inbox/` 里的材料按税表归位 |
| `essence-extraction` | 讲义提炼：PPT → 结构化笔记 + 插图 |
| `course-workspace-bootstrap` | 新课程工作区部署 |

---

## 两个说明

1. **课件原始材料不在本仓库。** 讲义 PPTX 与幻灯片截图版权归课程方所有，已单独备份至私有仓库。因此 `3_Essence/` 里笔记的图片链接在本仓库会失效——这是有意为之。

2. **本仓库不含 `.venv`。** 那是运行时环境，不是内容，约 104MB。
